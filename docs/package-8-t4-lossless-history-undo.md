## Purpose

Package 8-T4 adds a small, pure domain layer for preserving teacher revision history and performing lossless undo without rewriting prior evidence.

It builds only on the verified Package 8-T1/T2/T3 contracts.

## Required invariants

1. The automatic source revision remains immutable and is the first preserved revision.
2. Every later revision remains an immutable T1 `teacher_corrected` revision.
3. History is linear within this package and each appended revision must extend the exact current history revision.
4. Revision IDs and recursive lineage fingerprints must be unique inside one history.
5. Every non-root revision must have exactly one preserved transition event: T2 correction or T4 undo.
6. T2 correction audit events remain immutable and must bind the exact parent/result revision fingerprints and IDs.
7. T2 correction operations are deterministically replayed against the exact parent; the reproduced revision and audit semantics must match the preserved transition exactly.
8. T3 approval records remain immutable historical evidence and must bind an exact revision preserved in the history.
9. Undo never deletes, mutates, replaces, or re-labels an earlier revision.
10. Undo creates a new corrected revision from the current revision using the exact content of an earlier preserved revision.
11. Undo records exact current-parent, target, and result content/lineage fingerprints.
12. An undo target must be an earlier state and must not equal the current parent or current content.
13. Restored content may have the same `contentFingerprint` as the historical target, but the undo result has a new recursive `lineageFingerprint`.
14. An approval for the historical target does **not** automatically apply to the new undo result.
15. No identifier or timestamp is generated by the T4 domain layer.
16. Malformed, non-linear, duplicate, mutable, injected, forged or cross-source history evidence fails closed.

## History representation

One immutable history snapshot preserves:

- history/source identity;
- ordered immutable revisions;
- T2 correction audit events;
- T4 undo audit events;
- T3 approval records.

The history object and its arrays are immutable. Existing revision/audit/approval objects are preserved by exact reference; T4 does not clone or rewrite them.

## Correction evidence integrity

T4 does not trust a shape-valid T2 audit record merely because its top-level parent/result IDs and fingerprints match.

For every preserved correction transition, T4 reconstructs the exact correction request from the immutable audit operations, replays it against the exact parent with `applyTeacherCorrectionBatch`, and requires:

- reproduced revision timestamp to match;
- reproduced recursive lineage to match;
- reproduced operation evidence, including `before` and `after`, to match exactly.

This closes the review case where a forged but schema-valid audit operation could claim a false previous value while still pointing at a real revision.

## Undo semantics

Undo is **not** pointer mutation and is **not** deletion.

For a current history:

```text
A0 -> R1 -> R2
```

undoing to `R1` creates:

```text
A0 -> R1 -> R2 -> R3(undo content of R1)
```

`R3.contentFingerprint` equals `R1.contentFingerprint`, but `R3.lineageFingerprint` differs because `R3` has `R2` as its exact parent lineage.

Therefore an approval bound to `R1` remains historical evidence for `R1` and evaluates as non-applicable to `R3` unless a teacher explicitly approves `R3` later.

History validation also rejects externally reconstructed impossible undo evidence that targets the current parent or reproduces the current parent content.

## Review hardening

PR #97 was not merged merely because its first complete implementation CI was green. Two integrity findings were resolved before final merge:

1. **Correction audit replay integrity:** a shape-valid correction audit could lie about operation-level `before` evidence. T4 now replays the exact operation set and compares reproduced revision/audit semantics.
2. **Reconstructed current-parent undo:** a manually assembled history could encode an undo target that the public creator would reject. Validator and creator semantics now both reject current-parent/same-content undo targets.

Focused regression files added during hardening:

- `tests/teacherRevisionHistoryIntegrity.test.js`
- `tests/teacherRevisionHistoryUndoIntegrity.test.js`
