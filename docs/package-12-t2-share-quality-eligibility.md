## Purpose

Package 12-T2 adds the second bounded layer of the teacher-to-student sharing system.

T1 answers only:

> Did the teacher explicitly authorize this exact approved revision for this exact recipient label?

T2 additionally asks:

> Does this revision still match an exact source NoteObject array that currently owns sufficient source and quality evidence to be eligible to leave the teacher boundary?

T2 returns **eligibility metadata only**. It does not build, expose or transmit student content.

## Safety inputs

T2 reuses existing verified boundaries rather than inventing a new musical truth engine:

- Package 8 immutable revision identity and recursive lineage;
- Package 8 exact teacher approval;
- Package 12-T1 exact authorization + recipient + revocation;
- Package 7C exact-array raw MusicXML source provenance;
- Package 2C frozen quality/error report;
- Package 2D TTS and playback quality gates.

## Critical source-array distinction

Package 8 revisions are immutable snapshots. `createAutomaticRevision(...)` clones the caller's musical content so `revision.content` is intentionally **not** the same object identity as the original NoteObject array.

Package 7C and Package 2D, by contrast, intentionally bind source/report evidence to an **exact NoteObject[] identity** through WeakMap-backed registries.

T2 therefore never pretends that `revision.content` owns the original Package 7C/2D evidence. The caller supplies `sourceNotes` explicitly.

Before reading any quality evidence, T2 deterministically recreates the automatic Package 8 snapshot from `sourceNotes` using the existing revision model and requires:

- the same source revision identity;
- the same content fingerprint;
- the same recursive lineage fingerprint.

If the source array changes after evidence issuance, or does not reproduce the approved automatic revision, evaluation fails closed as stale source evidence.

## Exact quality evidence

`src/services/teacherShareEligibility.js` introduces an immutable `share_quality_eligible` evidence record.

Evidence is created only when the supplied exact `sourceNotes` array:

1. deterministically reproduces the exact automatic Package 8 revision snapshot;
2. owns an exact-array Package 7C MusicXML source record;
3. owns a frozen accepted Package 2C report with structurally valid and source-verified state;
4. has zero report errors, warnings and unverified notes;
5. resolves TTS gate = `ACCEPT / verified-structurally-valid`;
6. resolves playback gate = `ACCEPT / verified-structurally-valid`.

The evidence binds:

- source ID and source revision ID;
- exact revision ID and kind;
- parent/lineage fields;
- revision timestamp;
- content fingerprint;
- recursive lineage fingerprint;
- MusicXML source provenance;
- deterministic MusicXML text fingerprint;
- TTS/playback decisions and reasons;
- caller-supplied evidence ID/time.

No ID or timestamp is generated by the domain layer.

## Exact-array semantics

Evidence registered against one NoteObject array never transfers automatically to another array.

A clone can become independently eligible only if the existing Package 7C/2D preparation flow is explicitly run for that clone and it independently reproduces the same automatic revision snapshot. This is fresh exact-array evidence, not evidence transfer.

`revision.content` itself cannot silently inherit the original source array's Package 7C/2D evidence.

## Live re-check

An issued T2 evidence record is not treated as permanently sufficient.

`evaluateTeacherShareEligibility(...)` re-checks:

- T1 authorization/recipient/revocation applicability;
- automatic revision kind;
- quality-evidence binding;
- current `sourceNotes` → revision fingerprint/lineage equality;
- current exact-array MusicXML source;
- current Package 2D gates;
- current strict Package 2C accepted-report shape.

Therefore:

- missing `sourceNotes` fails closed;
- source-array content drift is stale;
- removed source evidence fails closed;
- replaced source evidence is stale;
- removed report becomes quality review;
- a newly blocked report becomes quality blocked;
- an optimistic ad-hoc object that makes Package 2D return `ACCEPT` is still rejected if it does not satisfy the stronger frozen Package 2C accepted-report shape;
- T1 recipient mismatch, revocation or stale authorization stops evaluation before quality eligibility.

## Critical corrected-revision boundary

Package 8 teacher editing intentionally does not recalculate dependent musical/source-verification fields. A teacher-corrected revision can therefore contain source-verification metadata inherited from its parent even after a teacher changes an editable value.

For this reason **T2 v1 never creates quality eligibility evidence for `teacher_corrected` revisions**, even if an existing Package 2D adapter appears optimistic.

Teacher-corrected revisions return:

`corrected_revision_revalidation_required`

until a separately reviewed post-correction validation/provenance contract exists.

This prevents old automatic-source evidence from being silently reused after a correction.

## Eligibility states

T2 uses explicit fail-closed states:

- `eligible_exact_revision`
- `authorization_not_applicable`
- `recipient_mismatch`
- `revoked`
- `corrected_revision_revalidation_required`
- `quality_evidence_missing`
- `quality_evidence_not_applicable`
- `source_evidence_missing`
- `source_evidence_stale`
- `quality_review_required`
- `quality_blocked`
- `quality_evidence_invalid`
- `quality_evidence_stale`

Only `eligible_exact_revision` returns `eligible: true`.

## Explicit non-goals

T2 does **not**:

- return revision content or MusicXML;
- create a student payload or any payload bytes;
- add a public/private share link;
- generate bearer tokens, passwords or invite codes;
- authenticate teacher or student identities;
- persist authorization/evidence;
- add a database;
- add backend/API endpoints;
- send network requests;
- send email/messages;
- change Package 8 correction semantics;
- weaken Package 7C/2D exact-array identity;
- change OMR/Audiveris/provider/runtime/model selection;
- change `Dockerfile`, `render.yaml` or Render wiring;
- add dependencies.
